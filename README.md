A small, self-hosted autoplay / "Instant Mix" service for **Navidrome**.

I built this for my own music library because I wanted Instant Mix to work a little more the way I'm used to from streaming services: songs that stay close to the mood of the song I started with, a different mix each time, and a smooth flow from one track to the next. It works well for me, so I'm sharing it in case it's useful or interesting to someone else.

> [!NOTE]
> **This project was created with AI.** All of the code, this repository, and its documentation were generated by an AI coding assistant (Gemini 3.8 Flash and Opus 5.5), with me guiding it and testing the results on my own server. Please read through it before you run it, and expect rough edges. It's a personal hobby project, not a polished product.

## What it does

When you start an Instant Mix from a song, the service builds a queue that tries to:

* **Stay close to the starting song.** Each candidate is compared to the song you started with *and* to the song that just played, so the mix doesn't slowly wander into an unrelated genre.
* **Feel a bit different every time.** A small amount of randomness is added among the good matches, so starting a mix from the same song twice gives you two different queues.
* **Flow nicely.** Where BPM and key information is available, it prefers songs with a similar tempo (counting half-time and double-time) and compatible keys on the Camelot wheel.
* **Avoid repetition.** It limits how often the same artist shows up and removes duplicate songs that appear on several albums or compilations.
* **Include songs you've never played.** Albums, artists, scrobbles, and playlists are combined into one similarity map, so tracks without any play history can still be recommended.

The ideas are loosely inspired by public write-ups on how Spotify and Apple Music approach autoplay. This is a hobbyist interpretation, not a reproduction of their systems.

### About AudioMuse-AI

Before this, I used [AudioMuse-AI](https://github.com/NeptuneHub/AudioMuse-AI) through its Navidrome plugin. It's a great project, and this one would not exist without it. On my small home server I wanted something lighter that uses my listening history, so I made this. It works with the existing AudioMuse-AI Navidrome plugin by providing the same API endpoints. If AudioMuse-AI already works well for you, there's probably no reason to switch.

## How it fits together

```
                      [ Navidrome / Subsonic client ]
                                    │
                                    ▼ (Instant Mix / Autoplay)
                   [ Navidrome plugin: audiomuseai.ndp ]
                                    │
                        GET /api/similar_tracks?item_id=X
                                    │
                                    ▼
       ┌────────────────────────────────────────────────────────┐
       │                  Navidrome Autoplay                    │
       │                                                        │
       │  1. Similarity map of the library (SVD)                │
       │  2. Compare to starting song + current song            │
       │  3. Keep within the same musical "scene"               │
       │  4. Tempo and key matching                             │
       │  5. A little randomness for variety                    │
       │  6. Artist limits and duplicate removal                │
       └────────────────────────────────────────────────────────┘
                                    │
                                    ▼
                         [ Queue of up to 100 songs ]
```

<details>
<summary><b>Technical details (for anyone curious)</b></summary>

#### 1. Similarity map
The engine builds a sparse graph that connects tracks through:
* **Same album** ($w=1.5$)
* **Same artist** ($w=0.8$)
* **Similar scene / artist name tokens** ($w=0.5$ – $2.0$), e.g. *Zillertal*, *Ambros*, *Ötzi*
* **Scrobbles and playlists**, weighted by how close together songs were played ($w = 1.0 / \Delta t$)

A 32-dimensional representation is then computed with `TruncatedSVD`, so every track in the library gets a vector, including ones with no play history.

#### 2. Two reference points
For candidate track $c$ and session history $H = [t_1, t_2, \dots, t_k]$, where $t_1$ is the starting song:

$$\text{Score}(c) = w_{\text{local}} S_{\text{svd}}(c, t_k) + w_{\text{macro}} S_{\text{svd}}(c, t_1) + w_{\text{art}} S_{\text{artist}}(c, t_k) + \text{Affinity}(c) - \text{Penalties}$$

with default weights $0.45$, $0.30$, and $0.25$. The starting song ($t_1$) keeps the overall mood, and the current song ($t_k$) keeps the next transition smooth.

#### 3. Variety (Gumbel-Top-$k$ sampling)
A small amount of Gumbel noise ($\tau = 0.20$) is added only to candidates above a minimum score:

$$S'_c = S_c + \tau \cdot g_c, \quad g_c = -\ln(-\ln(U_c)), \; U_c \sim \text{Uniform}(0, 1)$$

Strong matches still tend to come first, but the order and selection change from mix to mix. Poor matches stay below the cutoff and aren't affected.

#### 4. Tempo and key
* **Camelot wheel:** same or relative key $+0.20$, adjacent key $+0.12$, three or more steps away $-0.25$.
* **Tempo, counting half-time and double-time:**
  $$\Delta_{\text{BPM}} = \min(|BPM_c - BPM_{t_k}|, |BPM_c - 2 \cdot BPM_{t_k}|, |2 \cdot BPM_c - BPM_{t_k}|)$$
  so an 80 BPM song and a 160 BPM song are treated as a good fit.

</details>

## Observations from my setup

These are informal numbers from my own server (a library of about 6,400 tracks). Your results will probably differ depending on hardware and library size.

* Memory use is around 110 MB.
* A 100-song mix usually comes back in about 30 ms.
* The included analyzer processed roughly 12–15 tracks per second on 6 CPU cores, so my whole library took about 7 minutes.

## Installation

On the machine running Navidrome (Linux x86_64 or ARM64):

```bash
git clone https://github.com/hagenauc/navidrome-autoplay.git /opt/navidrome-autoplay
cd /opt/navidrome-autoplay
sudo ./install.sh
```

The install script:
1. Installs system packages (`ffmpeg`, `python3-dev`, `build-essential`, `libaubio-dev`).
2. Installs [`uv`](https://docs.astral.sh/uv/) (if not already present) and runs `uv sync --no-dev` to create `.venv` from `pyproject.toml` and `uv.lock`.
3. Sets up and starts a hardened systemd service (`navidrome-autoplay.service`).
4. Checks that the service responds locally on `127.0.0.1` ports **8000** and **8001**.

> **Note:** This service has **no Web UI** — it is a backend-only JSON API called by Navidrome's AudioMuse-AI plugin. By default it binds exclusively to `127.0.0.1` (`localhost`), which is all you need when running on the same machine as Navidrome.

Since the script runs as root and installs packages, please look through [install.sh](install.sh) before you run it.

## Audio analyzer (optional)

`analyzer.py` reads your audio files and estimates BPM, musical key (as Camelot codes), genre, and energy. Tempo and key matching only work for tracks that have this data.

```bash
cd /opt/navidrome-autoplay
# Run with 6 worker processes
uv run analyzer.py 6
```

Results are saved to `features.db` as the analyzer runs. The server reloads new results about every 15 seconds, so you don't need to restart it.

The server also checks `navidrome.db` every 15 minutes and analyzes newly added music in the background.

## Connecting it to Navidrome

This uses the existing **AudioMuse-AI Instant Mix** plugin for Navidrome.

1. In the Navidrome web UI, go to:
   **Settings** (gear icon) → **Plugins** → **AudioMuse-AI Instant Mix** → **Settings**.
2. Set **AudioMuse-AI API URL** to:
   ```
   http://127.0.0.1:8001
   ```
   *(`http://127.0.0.1:8000` works too.)*
3. Save.
4. Choose **"Instant Mix"** on any song in Navidrome or a Subsonic client (I've tried Amperfy, Symfonium, Feishin, and Substreamer).

## Configuration (`config.py`)

These settings can be changed with environment variables:

| Variable | Default | Description |
| :--- | :--- | :--- |
| `AUTOPLAY_HOST` | `127.0.0.1` | Bind address. Since there is no Web UI, `127.0.0.1` (localhost) is sufficient whenever Navidrome runs on the same machine. Only set `0.0.0.0` if Navidrome runs in an isolated container/host. |
| `AUTOPLAY_PORT` | `8001` | Main HTTP port (the service also listens on 8000) |
| `NAVIDROME_DB` | `/var/lib/navidrome/navidrome.db` | Path to Navidrome's SQLite database |
| `MACRO_ANCHOR_WEIGHT` | `0.30` | How strongly the mix stays close to the starting song |
| `LOCAL_TRANSITION_WEIGHT` | `0.45` | How strongly the next song follows the current one |
| `AUTOPLAY_TEMPERATURE` | `0.20` | Amount of variety (0.0 = the same mix every time) |
| `MAX_ARTIST_REPEAT_IN_QUEUE` | `2` | Maximum songs per artist in a queue |
| `BPM_TOLERANCE_PCT` | `0.10` | Tempo difference allowed before a penalty applies (10%) |
| `SESSION_TTL_SECONDS` | `7200` | In-memory session expiration time in seconds |
| `MAX_SESSIONS` | `1000` | Maximum number of active sessions kept in the LRU cache |
| `AUTOPLAY_API_KEY` | `""` | Optional API key required for `POST /api/reload` (`X-API-Key` header or `api_key` query param) |

## API endpoints

* `GET /health` or `GET /api/status`: Health check, uptime, and graph statistics.
* `GET /api/similar_tracks?item_id=<id>&n=10&eliminate_duplicates=true`: Song recommendations.
* `GET /api/similar_artists?artist=<name_or_id>&count=10`: Related artists.
* `GET /api/find_path?start_song_id=<id>&end_song_id=<id>&count=5`: A short path of songs connecting two tracks.
* `GET /api/analysis_status`: How much of the library has been analyzed.
* `POST /api/reload`: Reload the database and rebuild the similarity map after adding music (restricted to loopback unless `AUTOPLAY_API_KEY` is configured).
